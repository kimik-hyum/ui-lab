# 입력과 목록 갱신 분리

- 원본: `/front-feature/react/deferred-value`
- 디자인 데모: `#/features/react/deferred-value`
- 임베드: `/preview-embed/features/react/deferred-value`

양쪽 입력창에 한쪽씩 같은 문구를 연속 입력합니다. 왼쪽은 입력과 목록에 같은 `text`를 전달하고, 오른쪽은 입력에 `text`, 목록에 실제 `useDeferredValue(text)`를 전달합니다. **입력값 / 목록 기준값 / 갱신 중 표시**로 화면에 반영된 순서를 관찰합니다.

양쪽은 같은 120행과 `memo(SlowPreviewList)`를 사용합니다. 목록에는 `text`와 `workload` 원시값만 전달하므로 오른쪽은 값이 같을 때 이전 목록을 유지할 수 있습니다. 각 행은 별도 React 컴포넌트이며, 인공 작업도 각 행에서 수행해 React가 행 사이에 새 입력을 처리할 수 있게 합니다.

## 시연 조건

- 느린 목록: 각 행에서 1.5ms를 목표로 인공 작업을 수행합니다. 고정된 갱신 지연이나 실측 성능 수치는 아닙니다.
- 일반 목록: 인공 작업을 생략합니다. 두 방식의 차이가 눈에 띄지 않을 수 있습니다.
- 서버 렌더링과 빈 문구에서는 인공 작업을 생략합니다. 검색·필터·네트워크 요청은 없습니다.
- 좌우 입력은 독립적입니다. 양쪽 비우기는 두 값을 초기화합니다.
- UI·코드 전환 중 입력은 유지되며 UI로 돌아오면 목록을 다시 그립니다. 페이지를 벗어나면 입력은 사라집니다.

`useDeferredValue`는 목록 계산을 빠르게 만들거나 전체 작업량을 줄인다는 보장이 없습니다. 고정 시간 뒤 실행하는 debounce가 아니며, 요청 횟수를 줄여주는 기능도 아닙니다. 새 입력이 오면 진행 중이던 목록 렌더링을 다시 시작할 수 있습니다. [React 공식 문서](https://react.dev/reference/react/useDeferredValue#deferring-re-rendering-for-a-part-of-the-ui)

코드 비교는 실제 두 입력 컴포넌트와 공통 목록·행·작업 함수·상수·타입을 서버에서 읽어 표시합니다. 입력 연결, 목록 우선순위, memo와 이전 결과 유지의 세 토픽을 앵커로 연결합니다. 기존 공통 비교 컴포넌트는 그대로 사용합니다.
