## Nuxt에서 관찰된 차이

Nuxt의 LCP는 이전 5회가 약 2.73–3.13초, 현재 5회가 약 3.31–3.59초로 이번 실행에서는 모두 분리됐습니다. 단일 이상값만으로 생긴 차이는 아닙니다.

- LCP 요소는 두 버전 모두 동일한 상품 이미지이며 전송량도 약 124 KB로 같습니다.
- 중앙 점수 실행의 이미지 리소스 로딩 구간이 약 2.48초 → 3.09초로 늘었습니다. 렌더링 대기 시간은 약 8 ms로 유사합니다.
- 로컬 JavaScript·CSS 전송량도 약 220 KiB → 230 KiB로 늘었습니다.

이는 제한된 대역폭에서 리소스 전송 경로를 추가로 살펴볼 근거입니다. 외부 CDN 응답과 요청 경합도 포함되므로 프레임워크 자체의 처리 속도 저하로 확정하지 않습니다.

## 측정 조건

- production build, 서버 준비 후 축별 3회 예열. 현재 SSR → 현재 Lighthouse → 이전 SSR → 이전 Lighthouse 순서로 실행했습니다.
- 브라우저: DevTools 실제 제한, 다운로드·업로드 1,000 Kbps, 요청 지연 100 ms, CPU 1배. 실행마다 새 브라우저 프로필.
- SSR 도구→앱 및 앱→Supabase: HTTP 요청별 본문 1 Mbps, 요청 전 50 ms + 응답 전 50 ms 추가. 연결 재사용 없이 같은 조건을 적용합니다. GET/HEAD만 사용하므로 업로드 본문은 없습니다.
- 제한은 구간별로 적용됩니다. Supabase의 실제 통신·처리 시간은 추가로 포함되며, 전체 응답 시간이 100 ms로 고정되는 것은 아닙니다.
- 같은 프레임워크의 전후 SSR 조회 응답 SHA-256이 일치해 상품 데이터가 바뀌지 않았음을 확인했습니다. CPU·네트워크를 독점한 전용 장비 측정은 아닙니다.
- 이전/현재 lockfile을 그대로 설치했습니다. React·Vue·Vite 등 함께 업데이트된 의존성 영향도 포함됩니다.
