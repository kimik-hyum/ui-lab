# 앱 공통 규칙

`apps/` 아래에 적용합니다. 각 프레임워크의 route·data·mutation 관용구를 유지합니다.

## 구현
- 비교에 필요한 최소 구조를 사용합니다. UI 파일은 대표 UI 하나를 노출하되 프레임워크의 route convention export는 허용합니다.
- 화면은 표현과 UI 상태를 담당합니다. 데이터 접근·캐시 정책·비즈니스 계산은 시나리오의 data 모듈이나 프레임워크 데이터 계층에 둡니다.
- 서버 데이터와 URL 상태를 별도 상태로 불필요하게 복제하지 않습니다.
- 주요 데이터와 props의 타입을 명확히 하고, `any`와 검사 규칙 해제는 필요한 최소 범위에만 사용합니다.
- 초기 데이터는 프레임워크의 서버 로딩 API를 우선합니다. TanStack Query는 클라이언트 캐시·재조회·낙관적 갱신 등이 비교 목적일 때 사용합니다.
- 서버 전용 코드가 브라우저 번들에 들어가지 않도록 경계를 유지합니다.
- 오류·빈 데이터·not-found는 시나리오에 해당하는 프레임워크 경계에서 처리합니다.

## 비교 조건
- 같은 시나리오는 입력, fixture, 지연, 데이터 원본, 사용자 행동을 맞춥니다. 가격·날짜·숫자의 locale과 timezone도 고정합니다.
- 데이터 생성·정렬·필터링처럼 결과에 영향을 주는 계산은 찾아보기 쉬운 모듈에 둡니다.
- SSR, API 왕복, 클라이언트 캐시, 렌더링 비용을 구분하고 streaming/blocking 조건을 명시합니다.
- SSR 핵심 콘텐츠 도착은 `content-ready`로 비교합니다. 셸만 도착한 TTFB를 콘텐츠 도착 시간으로 해석하지 않습니다.
- 전역 provider·스타일·의존성을 추가할 때 다른 시나리오의 측정 조건에 미치는 영향을 확인합니다.
- 세부 측정·검증은 루트의 완료 기준과 `docs/harness/performance-methodology.md`를 따릅니다.
